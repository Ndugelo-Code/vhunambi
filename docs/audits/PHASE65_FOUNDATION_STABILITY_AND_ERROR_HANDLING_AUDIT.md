**Why the app dies reliably after audio triggers**:
1. [`vhunambi_audio_handler.dart`](file:///c:/Users/Ndugelo/VHUNAMBI/monorepo/apps/vhunambi_client/lib/features/player/data/services/vhunambi_audio_handler.dart#L61) defines `const String kAudioNotificationIcon = 'drawable/ic_stat_music';` and passes it into `AudioServiceConfig.androidNotificationIcon` at [line 797](file:///c:/Users/Ndugelo/VHUNAMBI/monorepo/apps/vhunambi_client/lib/features/player/data/services/vhunambi_audio_handler.dart#L797).
2. Recursive inspection of `apps/vhunambi_client/android/app/src/main/res/` proves **`drawable/ic_stat_music` does not exist** anywhere in the APK (only `drawable/launch_background.xml`, `drawable-v21/launch_background.xml`, `mipmap-*/ic_launcher.png`, `values/styles.xml`, and `values-night/styles.xml` exist).
3. Although [`bootstrapPlatformAudioHandler`](file:///c:/Users/Ndugelo/VHUNAMBI/monorepo/apps/vhunambi_client/lib/features/player/data/services/vhunambi_audio_handler.dart#L839-L858) wraps `AudioService.init(...)` in `try/catch`, `AudioService.init` only registers configuration lazily. When the user later generates a track, taps Play, taps a Library track, or toggles play/pause, `mediaItem.add(...)` / `playbackState.add(...)` executes `com.ryanheise.audioservice.AudioService.updateNotification()` on Android's native Java main Looper, throwing an uncatchable fatal `IllegalArgumentException` in OS space that terminates the process back to the phone home screen.

## 3. The Vhunambi 5-Layer Fault-Containment Architecture Blueprint

To eliminate OS process kills, isolate flaky plugins/decoders, and guarantee clean failure UX across all devices, Phase 65 installs the following 5 containment layers:

### Layer 1 — `VhunambiCrashShield` (Root Isolate & Framework Shield)
- **Target**: [`main.dart`](file:///c:/Users/Ndugelo/VHUNAMBI/monorepo/apps/vhunambi_client/lib/main.dart) + `apps/vhunambi_client/lib/core/resilience/vhunambi_crash_shield.dart`
- **Contract**:
  - `runZonedGuarded(() async { ... runApp(...); }, VhunambiCrashShield.recordZoneError)`
  - `FlutterError.onError = VhunambiCrashShield.recordFlutterError`
  - `PlatformDispatcher.instance.onError = VhunambiCrashShield.recordPlatformError` (returns `true` after logging + recording telemetry so recoverable async errors don't abort the UI isolate)
  - `ErrorWidget.builder = (details) => VhunambiSafeErrorCard(details: details)` (zero red screen of death in release/debug crashes)
  - `VhunambiProviderObserver extends ProviderObserver` logging provider errors to bounded ring buffer (`CrashBreadcrumbBuffer`).
  - Pre-`runApp` `SharedPreferences`, Hive bootstrap, and `bootstrapPlatformAudioHandler` each execute through `VhunambiCrashShield.guardStartup(name, timeout: 4s)` so `runApp()` always renders.

### Layer 2 — `SafeAudioOrchestrator` & Valid Notification Icon (Hardware Media Mutex)
- **Targets**:
  - `apps/vhunambi_client/android/app/src/main/res/drawable/ic_stat_music.xml` (24dp monochrome white note glyph matching Android notification guidelines)
  - [`vhunambi_audio_handler.dart`](file:///c:/Users/Ndugelo/VHUNAMBI/monorepo/apps/vhunambi_client/lib/features/player/data/services/vhunambi_audio_handler.dart) + [`just_audio_multi_stem_engine.dart`](file:///c:/Users/Ndugelo/VHUNAMBI/monorepo/apps/vhunambi_client/lib/features/player/data/services/just_audio_multi_stem_engine.dart) + [`player_provider.dart`](file:///c:/Users/Ndugelo/VHUNAMBI/monorepo/apps/vhunambi_client/lib/features/player/presentation/providers/player_provider.dart)
- **Contract**:
  - **Single-Active-Engine Mutex**: `SafeAudioOrchestrator.acquire(AudioEngineSlot slot)` enforces sequential lock acquisition (`masterPlayer`, `stemMixer`, `reelPool`, `sketchpad`), pausing/releasing competing engines before `setAudioSource` / `play`.
  - **Safe Media Operation Wrapper**: Every hardware ExoPlayer call runs under `_serializedQueue.add(() => op())` catching `PlayerException`, `PlayerInterruptedException`, `PlatformException`, and `TimeoutException`.
